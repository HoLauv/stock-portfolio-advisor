# 价值评分模型 v2.4.0

实现：`scripts/value_model.py`；CLI：`scripts/score_engine.py`。v1审查留档在 valuation-review-2026-09-05.md。
本版本修复口径、加入证据门槛与情景估值；参数是透明的工程规则，**尚未完成历史收益校准，不宣称收益提升**。

> v2.4.0 相对 v2.3.0 改了两处缺失数据口径：
> ① **大盘温度**改为"4 项里拿到 ≥3 项即出分、按可用项权重归一"，缺一两项不再让整个温度分变"数据不足"；
> ② **个股观测项缺失**不再一律计 0，改为**先补数据、能派生就派生、兜底给中性默认分 60**（`MISSING_FILL='neutral'`）。
> 两者都只影响"缺数据时的口径"，不改变数据齐全标的的分数。已有用户的评分基线一律重建（跨版本分差不计算）。
>
> v2.3.0（相对 v2.2.0）改了三处：股息子项、行业景气度派生、市场温度自算。三者都在模型内部派生，
> **不接受调用方直接塞入派生值**。

## 一、评分结构与缺失值

六维仍分别展示，但价值分只使用Q质量、G成长、V估值；F资金、T技术、N消息形成独立交易环境分，不影响价值评级。硬风险可以覆盖评级。

| profile | Q:G:V相对权重 | 适用 |
| --- | --- | --- |
| default | 25:20:20 | 通用盈利企业 |
| growth | 20:30:15 | 成长 |
| value | 30:10:30 | 成熟红利 |
| cyclical | 25:15:25 | 周期资源 |
| bank / broker / insurance | 30:10:25 | 银行/券商/保险，分别适配 |

价值分=`(Q×wQ+G×wG+V×wV)/(wQ+wG+wV)`。交易环境=`(15F+10T+10N)/35`。
保留v1的QGV相对权重，取消将交易热度混入价值的做法；交易环境采用统一15:10:10。

每项指标曲线输出0–100。维度分=`Σ(单项分×权重)/Σ计分权重`。缺失字段按**固定优先级**处置，顺序即原则——**能补就补，补不了才兜底**：

1. **补数据**（首选）：按 [data-playbook.md](data-playbook.md) 的取数路径把缺的字段取回来。兜底只是最后的无奈，不是第一选择。
2. **派生**：能从已有原始数据算出来的，引擎自己算，**不接受调用方直接塞入派生值**。目前可派生 `ocf_to_np`、`np_yoy`（见第二节）、`dividend_spread_pct`/`dividend_coverage`（见第二、三节）、`industry_boom`（见第二节）以及大盘温度的三个指标（见第四节）。
3. **结构性缺失**（`IMPUTE` 白名单：`forecast` 无机构覆盖、`industry_boom` 无行业数据）：第三方来源缺失，不掌握在公司手上，按**总体期望分**插补并计入 `data_quality.<维度>.imputed` 与 `notes`。`forecast` 的期望分=0.25×beat100+0.40×inline70+0.15×flat40+0.20×miss0≈60；`industry_boom` 取中性50。两者合计权重30，因此同时缺失时该维度按v2.1旧口径少算17.0分——这正是v2.2修掉的问题：把"没有机构覆盖"当成了"成长性差"。
   `industry_boom` 的 50 分只是**兜底**：只要有申万行业财报就改用派生值（见第二节），插补只在行业数据也取不到时才发生。
4. **观测项缺失**（公司自己应披露的财务/资金/技术等：ROE、毛利率、负债率、经营现金流、资金流、技术形态……）：按常量 `MISSING_FILL` 兜底，**默认 `neutral`**——给**中性默认分 60**（`NEUTRAL_FALLBACK`）并计入 `data_quality.<维度>.neutral`，**仍留在计分分母里**。
   备选 **`renorm`**（把该权重整块退出计分分母、按剩余项归一）需显式开启：归一会让"数据完整度不同的标的"失去可比性（少报几项的分数会虚高），而本 skill 的核心用法是跨快照跟踪评分 Δ，口径必须稳定，所以默认 `neutral`。

**两个分母是分开的，这点很关键**：`all_weight`（所有适用项权重）只用来算**有效覆盖率**，`used_weight`（实际计入计分的权重）只用来算**维度分**。兜底与插补都**不抬高覆盖率**——`neutral` 下 `used_weight=all_weight`，只有 `renorm` 才小于。有效覆盖率=`真实数据权重/all_weight`，**只统计真实数据**；低于70%（`MIN_COVERAGE`）时维度分为null，因此**兜底/插补/归一都不会让资料不足的标的绕过NR门槛**。70%为工程门槛，不是统计置信度。
已知亏损的非金融企业移除Q中的现金流/净利与盈利CV项并按剩余项归一化；没有利润数据不等于已知亏损。

**已知偏置（v2.4.0 起，已接受的取舍）**：只要兜底值大于0，两类倒挂就消不掉——
① 无机构覆盖的标的（`forecast` 插补60）会高于有覆盖但预期落空（`forecast=miss`）的标的；
② 漏报观测项的标的（`neutral` 兜底60）会高于如实上报差数据（该项真实分低于60）的标的。
这是"不给缺失任何好处"与"跨快照口径稳定"两个目标之间的固有冲突：v2.4.0 选了后者（可跟踪 Δ），因此**放弃**用"缺失计0"来惩罚漏报。缓解手段：先尽最大努力补数据；横向比较时查看 `data_quality.*.imputed` 与 `data_quality.*.neutral`，这两处会点名哪些分是插补/兜底来的。

Q/G/V均有分、关键财务数据齐全、有效现价与完整情景估值齐全、风险已核查，才发布总分及评级。
普通企业关键字段为ROE、净利润TTM、经营现金流TTM；银行为ROE、不良率、核心一级资本缓冲；券商为正常化ROE、风险覆盖率；保险为正常化ROE、核心偿付能力。
资料不足输出NR/暂不评级，总分null、仓位上限null；已知ST/退市/立案则仍强制D、上限0，不让缺失数据掩盖硬风险。

## 二、质量与成长

普通企业Q沿用ROE30、毛利15、净利率15、负债率15、现金转化15、稳定性10的结构；插值端点见代码常量Q。
现金转化由同期`operating_cashflow_ttm/net_profit_ttm`直接重算，净利润必须为正；不接受输入比值替代分子符号。
CV需至少3个年度样本与正均值认证，否则缺失。

**股息覆盖（v2.3.0 新增，可选启用）**：有股息数据时追加 `dividend_coverage`（权重10），
取值由 `net_profit_ttm / cash_dividend_ttm` 重算，衡量盈利能否覆盖派息。
追加时其余Q项权重按 0.9 等比压缩，**权重总和恒为100**——不压缩的话分母变成110，
等于给原有每一项悄悄降权，Q 会随是否启用股息而无故漂移。
曲线 `0.8→0 / 1.2→45 / 1.7→75 / 2.5→100` 倍。缺少有效无风险利率或现金分红时整块不启用、不进分母。

| 金融子行业 | Q指标及权重 |
| --- | --- |
| bank | ROE30；拨备覆盖20；不良率25；核心一级资本相对该银行适用监管要求的缓冲25 |
| broker | 正常化ROE35；风险覆盖率35；净资本/净资产30 |
| insurance | 正常化ROE30；核心偿付能力35；综合偿付能力35 |

金融Q不使用负债率加分，不把银行拨备覆盖率套给保险/券商。`financial`旧档位必须由行业解析为子行业，否则NR。
银行ROE≥12%对应该项100分。银行缓冲不是资本充足率本身；监管要求必须从有效监管文件及该银行适用要求核实后计算。

G：营收增长25、盈利增长30、单季趋势15、预期兑现20、行业景气10。
`forecast` 属结构性缺失白名单：无机构覆盖时按期望分（60）插补，不按0计；其余G项缺失按 `neutral` 兜底给60（见第一节），不再一律计0。

**行业景气度（v2.3.0 改用派生）**：`industry_boom` 不再接受调用方手填，改由申万行业财报TTM同比派生——

- 输入 `sector_np_yoy_pct`（行业净利同比，必填）与 `sector_rev_yoy_pct`（行业营收同比，可选）
- 净利权重70、营收权重30；只有净利时按净利单口径给分
- 净利曲线 `-20→0 / 0→35 / 10→60 / 25→85 / 50→100`；营收曲线 `-10→0 / 0→40 / 10→70 / 25→100`
- 派生值**覆盖**手填值；行业数据过不了证据门槛（无来源/过期）时退回手填，再没有才走期望分插补50

为什么改：手填一个 0–100 的中性值等于让所有标的拿到同一个数，"不含个股信息"。
派生后同一行业内的标的按行业景气分化，不同行业之间也有区分。
`data_quality.<维度>.imputed` 只列真正走了插补的项，因此派生成功时该维度不再出现 `industry_boom`。
周期企业的盈利增长项改为`cycle_recovery`；券商/保险改为`normalized_profit_growth_pct`；其他已亏损企业改为`loss_recovery`。
普通净利同比只有上年同期利润为正才可用。季节性企业优先同比、经季节性解释的环比；模型不能凭空识别季节性。

**净利同比自算（v2.4.0 新增派生）**：缺 `np_yoy` 时，若同时有正 `net_profit_ttm` 与正 `prior_net_profit`，且两者 `period_end` 相差约一年（`one_year_apart`，350–380 天窗口），引擎按 `(net_profit_ttm/prior_net_profit-1)×100` 自算，并在 `notes` 写明公式。
调用方已给 `np_yoy` 则尊重其口径不覆盖；两侧窗口对不上（防止拿错半年报/季报硬算同比）或任一侧非正时不派生，交由后续兜底。
`prior_net_profit` 非正时即使有值也会被剔除，因为负基数上的"同比增长率"没有可比含义。

## 三、估值V与公允价值

V：公允价值安全边际60、适用历史估值分位20、可比公司折溢价20。
安全边际=`(1-现价/基准公允价值)×100`；-50/-20/0/20/40映射0/20/50/75/100分。

**股息利差（v2.3.0 新增，可选启用）**：有股息数据时 V 让出权重给 `dividend_spread_pct`，
变为 安全边际50 / 估值分位15 / 可比折溢价15 / **股息利差20**，分母仍为100，不稀释其他标的。
利差=`dividend_yield_pct − risk_free_rate_pct`（无风险利率取市场级 `market.risk_free_rate_pct`，10年期国债），
曲线 `-1→0 / 0→50 / 1→80 / 2.5→100` 个百分点。股息率低于无风险利率时利差为负，按 0 分处理。

**股息为什么拆成两处**：利差衡量"现金回报的吸引力"，属估值 → 放 V；
盈利覆盖倍数衡量"派息能不能持续"，属质量 → 放 Q。两者不重复计分，
报告会分别给出 `spread_score` 与 `coverage_score`，便于核对持有理由是否被正确计入。

> **可选启用的已知偏置**：股息子在数据齐备时才进分母。这意味着同一只高Q标的，
> 补上股息数据后若其覆盖分低于原有各项，Q 会下降（评估了更多信息，结果自然可能变差）。
> 反过来，不提供股息数据则完全不受影响。缓解办法是**对红利类档位始终取股息数据**，
> 让横向比较建立在同一口径上；报告与 `notes` 会明确标注本次是否启用。

上行空间=`(基准公允价值/现价-1)×100`，与安全边际不是同一数值。
金融与周期使用PB分位；其余已知亏损企业用PS；其余用PE。亏损股没有PE时不会误认为“历史最便宜”。
辅助分位仅作相对定价比较，不能单独生成公允价值。可比折溢价的`multiple`必须与PE/PB/PS选择一致。
历史序列需时点口径且至少36个月；尽量使用60个月，明确缩短样本原因。PEG不再参与评分，可用`calc_peg(PE,预测增长百分数)`辅助展示。

### 方法路由

| profile | 可用主方法 |
| --- | --- |
| default | normalized_pe / fcfe / fcff |
| growth | normalized_pe / fcfe / fcff / ev_sales |
| value | normalized_pe / ddm / fcfe / fcff |
| cyclical | normalized_pe / ev_ebitda / fcfe / fcff |
| bank | justified_pb / ddm / fcfe |
| broker | justified_pb / normalized_pe / ddm / fcfe |
| insurance | embedded_value / ddm / fcfe |

每次选一种适用主模型，提供bear/base/bull三套输入。行业不适配、输入不完整、非法倍数、非正股权价值、情景顺序错误均不出公允价值，不做技术位兜底。
PB历史中枢不再直接当合理PB；PE历史中位数不再机械乘EPS。合理倍数需可比企业、增长与盈利质量的依据。

全部方法输出**估值日当前公允价值**，`horizon=current_fair_value`。未来12个月价格不是本版本输出目标；不得混合期限。
券商目标价独立显示：≥3个去重机构、90日内、有来源及预测期限；技术压力位独立显示，二者不参与公允价值/价值评分。

完整字段和公式见 [indicator-mapping.md](indicator-mapping.md)。

## 四、风险与配置

`risk.status`区分not_checked/failed/checked；只有checked、有效来源与7日内数据、events为列表才算核查完毕。无风险为[]，未查询为null。
ST/*ST/退市/立案优先D；非金融资产负债率>90且**经营现金流金额<0**时总分封顶49；大股东减持>2%、商誉/净资产>30%分别下调一档。事件应使用标准中文标签；普通英文包含st不等于ST。

大盘温度保留均线、成交额、涨跌广度、破净比例4项，权重30:20:20:15。**4 项里拿到 ≥3 项（`MIN_MARKET_ITEMS`）就出温度分**，分母改用**可用项的权重和**（按权重归一），不再要求四项全齐——旧口径缺任意一项就让整个温度分变成"数据不足"，等于让缺数据掩盖已有信息；不足 3 项才输出"数据不足"。
`market.coverage` 给出可用权重占比，`market.used`/`market.missing` 列出用上/缺失的项，`market.min_items` 记录门槛（=3），`notes` 写明"温度分由 N/4 项按权重归一得出（可用权重 …，覆盖率 …%）"。取消北向20日净流入依赖。冰点不再自动触发高仓位。

**指标自算（v2.3.0 新增）**：四个指标里三个可以自己算，不必等现成值——

| 派生指标 | 原始序列（放 `market`） | 最少样本 | 算法 |
| --- | --- | --- | --- |
| `hs300_ma250_dev` | `hs300_close_series` | 250 | `(最新/近250日均值-1)×100` |
| `volume_ratio_5_250` | `turnover_series`（全市场成交额，用于近似量能） | 250 | `近5日均值/近250日均值` |
| `up_ratio_20d` | `advance_ratio_series`（逐日上涨家数占比，%） | 20 | `近20日均值` |

- **显式给值优先**：某指标已有现成值就不再自算，两条路径可混用。
- **序列必须自带 `indicator_meta.<序列名>`**：派生值继承来源序列的 meta 后照常过证据门槛，不走后门。
- 序列长度不足、含非有限值、成交价/成交额出现 ≤0、上涨占比超出 0–100 时，该序列整体作废并保持缺失。
- `market.derived` 会列出本次哪些指标是自算的，`notes` 同步写明，便于区分"市场真的没数据"与"我们替你算了"。
- `broken_net_ratio`（破净家数比例）无法从行情序列推导，仍需外部提供。

配置必须有完整持仓、总资产分母、风险承受度、期限、回撤容忍、现金需求、用户权益预算、其他资产权重及近期可交易状态。任一持仓NR或风险未核查，整个配置暂停，防止把未知持仓当成应清仓。
约束：单票评级上限≤15%，行业≤30%，产业链分组≤30%，现金≥max(5%,现金需求)。前三大≤45%由单票上限自然保证，比55%约束更严格。
目标权重按 merit（总分−45）比例填充，同一轮内同步提交增量，分组额度不足时先按merit比例压缩该组额度、再套用单票上限；逐只顺序提交会让代码排序靠前的标的先占满分组额度，结果依赖代码顺序而不是评分，v2.2已修正。
C/D的目标为0；无合格标的时权益实际配置0，余量明确计入现金。总权益+现金+其他资产=100%。
输出为`reference`约束预算参考，不自动加仓/减仓，不生成订单；仍需人工核对费用、最小交易单位与实际成交性。风险承受度/期限/回撤作为用户政策记录，算法不推断最优预算，也不保证回撤限制。

## 五、快照与验证

结果带`model_version=2.4.0`与各股票`weights_version`。与其他模型版本或不同profile的快照不直接计算分差；遇到NR也重建基线。v2.2改了缺失值口径与配置填充算法、v2.3改了股息子项与两个派生口径、v2.4把个股观测项缺失由"计0"改为"中性兜底60"并把大盘温度改为≥3项归一，已有用户的基线一律重建。
同版本同档位按旧权重计算数据变化贡献，另外列出调权影响与红线/舍入项，不从单次分差直接生成交易动作。

v2.1支持读取config/weights.json中的已验证历史调权版本；按分析日选择已经生效、未过期且无未来标签的权重。详见[历史回测与自动调权](backtesting.md)。上表为内置回退权重，正式报表会显示实际使用权重。

回归检查：`python -B -m unittest discover -s scripts -p "test_*.py" -v`。
测试使用人工数据验证公式、缺失值、行业路由、风险、仓位约束和报告兼容性，**不是历史收益回测**。
历史校准仍需按公告可得时点构建含退市样本的数据集、滚动验证、分红复权与交易成本；没有这些输入，不声称已回测。
